send\_reply\_start\_transaction
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. container:: everest-api op send

   .. raw:: html

      <div class="op-head">
      <span class="badge send" title="Published by the client, consumed by EVerest">send</span>

      <span class="op-title">Send reply for start transaction</span></div>
      <dl class="op-facts">
      <dt>Topic</dt>
      <dd>Dynamic: the <code>replyTo</code> address from the request's headers.

   Request to reply.

   This operation is used to handle the request to start a new transaction on the powermeter (for signed metering according to German Eichrecht).

      <div class="msg-summary"><p>The start transaction reply message contains the request status. It indicates whether the transaction could be started successfully or not. Further values may be added to the message depending on the value of the status.</p></div><div class="msg-grid">
      <div>
      <p class="msg-section">Payload</p>
      <details class="s-node s-top" data-inline="schema-StartTransactionReply" open>
      <summary><span class="s-type">object</span> <a class="s-ref" href="#schema-StartTransactionReply" title="powermeter_API.yaml">StartTransactionReply</a></summary>
      <div class="s-desc"><p>Return value when a transaction is started.</p></div><p class="s-inline"><a href="#schema-StartTransactionReply">Definition of StartTransactionReply</a></p>
      </details>

      </div>

send\_reply\_stop\_transaction
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. container:: everest-api op send

   .. raw:: html

      <div class="op-head">
      <span class="badge send" title="Published by the client, consumed by EVerest">send</span>

      <span class="op-title">Send reply for stop transaction</span></div>
      <dl class="op-facts">
      <dt>Topic</dt>
      <dd>Dynamic: the <code>replyTo</code> address from the request's headers.

      </dl>

   Request to reply.

   This operation is used to handle the request to stop the transaction on the powermeter and ask for the signed metering information in a reply.

   .. raw:: html

      <details class="msg">
      <summary><span class="msg-label">Message</span> <span class="msg-name">Stop transaction reply message</span> <code class="ctype">application/json</code></summary>

      <div class="msg-summary"><p>The stop transaction reply message contains the request status. It indicates whether the transaction could be stopped successfully or not. If successful the signed meter value report must be provided in this message too.</p></div><div class="msg-grid">
      <div>
      <p class="msg-section">Payload</p>
      <details class="s-node s-top" data-inline="schema-StopTransactionReply" open>
      <summary><span class="s-type">object</span> <a class="s-ref" href="#schema-StopTransactionReply" title="powermeter_API.yaml">StopTransactionReply</a></summary>
      <div class="s-desc"><p>Report returned when a signed transaction is requested to stop. If successful, includes the signed meter value object. In case of an error, an additional error message can be provided.</p></div><p class="s-inline"><a href="#schema-StopTransactionReply">Definition of StopTransactionReply</a></p>
      </details>

      </div>
      <div>

          &#34;encoding_method&#34;: &#34;string&#34;,
          &#34;public_key&#34;: &#34;string&#34;,
          &#34;timestamp&#34;: &#34;2019-08-24T14:15:22Z&#34;
        },
        &#34;error&#34;: &#34;string&#34;
      }</code></pre>
      </figure>

send\_capabilities

.. container:: everest-api op send

   .. raw:: html

      <div class="op-head">
      <span class="badge send" title="Published by the client, consumed by EVerest">send</span>

      <dl class="op-facts">

   Direction: Module to EVerest

   This operation is used to send the capabilities of the power meter. Optional: meters without restrictions do not need to publish this. If supported, publish at least once during start up and on every change. Absence of individual fields means no restriction.

      <div class="msg-summary"><p>Capabilities of the power meter, e.g. the minimum current above which the meter measures within its accuracy class (required by the German Calibration Law, Eichrecht). Publish at least once during start up and on every change if supported. Absence of individual fields means no restriction.</p></div><div class="msg-grid">
      <div>
      <p class="msg-section">Payload</p>
      <details class="s-node s-top" data-inline="schema-Capabilities" open>

      <div class="s-desc"><p>Capabilities of this power meter. All fields are optional; an absent field means no restriction / not supported.</p></div><p class="s-inline"><a href="#schema-Capabilities">Definition of Capabilities</a></p>
      </details>

      </div>
      <div>
      <p class="msg-section">Example</p>
