###############
entrypoint\_API
###############

.. warning::

   **Experimental API** since \2026.10.0.
   This API is exempt from the EVerest stability guarantees and the deprecation
   period. Its channels, operations and message payloads may change or be
   removed in any release without notice until it is promoted to stable. See
   the :ref:`policy on experimental components <project-experimental-components>`
   and the :ref:`experimental feature index <project-experimental-index>`.

.. _everest_api_entrypoint_API_op_receive_ready_beacon:

receive\_ready\_beacon
~~~~~~~~~~~~~~~~~~~~~~

.. container:: everest-api op receive

   .. raw:: html

      <div class="op-head">
      <span class="badge receive" title="Published by EVerest, consumed by the client">receive</span>

      <span class="op-title">Receive Ready Beacon</span></div>
      <dl class="op-facts">
      <dt>Topic</dt>
      <dd><code class="topic" data-copy="everest_api/ready_beacon">everest_api/ready_beacon</code></dd>
      </dl>

   Announces that the entrypoint API can be queried, subject to the conditions below. The payload is an empty JSON object and the message is not retained: a client connecting later never receives it and should send a discover request on its own. Clients must be prepared to receive this beacon more than once. Only if every API module is configured with 'allow\_global\_read: true' does the beacon guarantee that discover and query-modules/{api\_type} requests are answered; without that setting it guarantees nothing. The beacon never indicates that the API modules themselves are ready.
