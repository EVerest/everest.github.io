system_API¶

version 1.1.0AsyncAPI 3.0.0 content type application/jsonlicense Apache-2.0EVerestSystemAPI

EVerest API definition for the system module

API for EVerest API client implementing the system capabilities OTA update, log upload and network configuration. Commands without arguments carry an empty JSON object ({}) as payload.

Specification: system_API.yaml · pionix:de:everest:system_API

send the client publishes, EVerest consumes (10) receive EVerest publishes, the client consumes (9)

Servers¶

default mqtt

default local MQTT

Host
localhost:1883
Topic prefix
everest_api/1/system/{module_id}
{module_id}

The ID of the module as defined in the EVerest config file.

Operations¶

Client to EVerest¶

send_reply_update_firmware¶

send Reply to update firmware request
Topic
Dynamic: the replyTo address from the request's headers. Answers receive_request_update_firmware.

Direction: Module to EVerest

Message Reply update firmware application/json

Message send_reply_update_firmware

Reply to update firmware request.

Payload

string UpdateFirmwareResponse

Enum for the response of an update_firmware command

  • Accepted: Accepted this firmware update request. This does not mean the firmware update is successful, the system will now start the firmware update process
  • Rejected: Firmware update request rejected
  • AcceptedCanceled: Accepted this firmware update request, but in doing this has cancelled an ongoing firmware update
  • InvalidCertificate: The certificate is invalid
  • RevokedCertificate: Failure end state. The Firmware Signing certificate has been revoked
enumAcceptedRejectedAcceptedCanceledInvalidCertificateRevokedCertificate

receive_allow_firmware_installation¶

receive Call to allow a firmware installation to proceed
Topic
everest_api/1/system/{module_id}/e2m/allow_firmware_installation

Direction: EVerest to Module

Message Receive Allow firmware installation application/json

Message receive_allow_firmware_installation

Call to allow firmware installation to proceed

Call to allow a firmware installation to proceed. This is usually called after a firmware update has been downloaded. OCPP requires to move all EVSE to an unavailable state prior to installing new firmware. EVerest will take care of this and call this function when all EVSE are in unavailable state to signal that installation can proceed.

Payload

No payload.

Schemas¶

BootReason string¶
string

Enum defining the boot reason

enumApplicationResetFirmwareUpdateLocalResetPowerUpRemoteResetScheduledResetTriggeredUnknownWatchdog
FirmwareUpdateRequest object¶
object

Type defining a Firmware update request

Additional properties allowed.

  • retriesinteger

    This specifies how many times the system must try to download the firmware before giving up.

    min 1
  • retry_interval_sinteger

    The interval in seconds after which a retry may be attempted

  • request_idinteger required

    The Id of this request. If the originating firmware request (e.g. from the OCPP CSMS) did not include a request_id (e.g. classic UpdateFirmware.req), a request_id of -1 is used.

  • locationstring required

    URI defining the origin of the firmware

  • retrieve_timestampstring

    Time when the firmware update shall be retrieved in RFC3339 format

    format date-time

FirmwareUpdateStatusEnum string¶
string

State describing the current download/upload status of a firmware update of the system:

  • Downloaded: Intermediate state. New firmware has been downloaded by System
  • DownloadFailed: Failure end state. System failed to download firmware
  • Downloading: Intermediate state. Firmware is being downloaded
  • DownloadScheduled: Intermediate state. Downloading of new firmware has been scheduled
  • DownloadPaused: Intermediate state. Downloading has been paused
  • Idle: System is not performing firmware update related tasks
  • InstallationFailed: Failure end state. Installation of new firmware has failed
  • Installing: Intermediate state. Firmware is being installed
  • Installed: Successful end state. New firmware has successfully been installed in System
  • InstallRebooting: Intermediate state. System is about to reboot to activate new firmware
  • InstallScheduled: Intermediate state. Installation of the downloaded firmware is scheduled to take place on installDateTime
  • InstallVerificationFailed: Failure end state. Verification of the new firmware (e.g. using a checksum or some other means) has failed and installation will not proceed. (Final failure state)
  • InvalidSignature: Failure end state. The firmware signature is not valid
  • SignatureVerified: Intermediate state. Provide signature successfully verified
enumDownloadedDownloadFailedDownloadingDownloadScheduledDownloadPausedIdleInstallationFailedInstallingInstalledInstallRebootingInstallScheduledInstallVerificationFailedInvalidSignatureSignatureVerified
