Module Configuration
====================
| **device**: *string* <optional>
| *default: "eth0"*
|  Ethernet device used for HLC. Any local interface that has an ipv6 link-local and a MAC addr will work
| **logging_path**: *string* <optional>
| *default: "."*
|  This option should no longer be used and will be removed in the future. Path to logging directory (will be created if non existent)
| **tls_negotiation_strategy**: *string* <optional>
| *default: "ACCEPT_CLIENT_OFFER"*
|  Select strategy on how to negotiate connection encryption. TLS needs a V2G leaf certificate from the security module; when none is installed the SECC still starts and offers unsecured sessions only (ISO 15118-2 with EIM, DIN SPEC 70121), except with ENFORCE_TLS, which then refuses to start.
|  enum:
|    - ACCEPT_CLIENT_OFFER
|    - ENFORCE_TLS
|    - ENFORCE_NO_TLS
| **enforce_tls_1_3**: *boolean* <optional>
| *default: False*
|  Enforcing tls version 1.3. Applies whenever a TLS connection is established, independently of tls_negotiation_strategy: it pins the min/max protocol version, the cipher list and the client_hello certificate-verify elevation. Set to true for ISO 15118-20 (mandates TLS 1.3 mTLS). Set to false to offer TLS 1.2 (cipher ECDHE-ECDSA-AES128-SHA256, no client-certificate request), which is required for ISO 15118-2 / DIN SPEC 70121. With it unset the TLS version follows the EV's offer, and the SECC leaf is chosen per connection to match: a prime256v1 leaf (ISO 15118-2) is presented on TLS 1.2, a secp521r1 / Ed448 leaf (ISO 15118-20) on TLS 1.3, so install both leaves in the security module's SECC leaf directory when offering both protocols. Multi-chain selection works on both TLS 1.2 (driven by the trusted_ca_keys extension) and TLS 1.3 (driven by the native certificate_authorities extension), so multiple V2G leaf chains can be installed concurrently regardless of this flag.
| **supported_DIN70121**: *boolean* <optional>
| *default: False*
|  Offer DIN SPEC 70121 (DC only) in the SupportedAppProtocol handshake. Negotiated with the lowest priority (after ISO 15118-20 and ISO 15118-2).
| **supported_ISO15118_2**: *boolean* <optional>
| *default: False*
|  Offer ISO 15118-2 (AC and DC) in the SupportedAppProtocol handshake. Negotiated with a lower priority than ISO 15118-20 but higher than DIN SPEC 70121.
| **supported_ISO15118_20**: *boolean* <optional>
| *default: True*
|  Offer ISO 15118-20 (AC and DC) in the SupportedAppProtocol handshake. Negotiated with the highest priority. At least one of supported_ISO15118_20, supported_ISO15118_2 and supported_DIN70121 must be enabled. ISO 15118-20 is TLS-only ([V2G20-2677]), so it is silently dropped from the offer when no V2G leaf certificate is available; ISO 15118-2 and DIN SPEC 70121 keep running unsecured in that case. When a certificate IS available, -20 stays in the offer even on unsecured connections (ENFORCE_NO_TLS, or an EV requesting no transport security): such a session works but is not standard-conformant, and is logged as a warning. Set this to false to offer only ISO 15118-2 / DIN SPEC 70121 on unsecured deployments.
| **auth_timeout_eim**: *integer* <optional>
| *default: 300*
|  Defines how many seconds the EVSE should wait for authorization in EIM (External Payment) case, before the charging session is aborted. Write 0 if the EVSE should wait indefinitely for EIM authorization. Applies to ISO 15118-2 and DIN SPEC 70121; ISO 15118-20 EIM stops the session after the 55 s V2G_SECC_Ongoing_Performance_Time ([V2G20-2102]).
| **auth_timeout_pnc**: *integer* <optional>
| *default: 55*
|  Defines how many seconds the EVSE should wait for authorization in PnC (Contract) case, before the charging session is aborted. Write 0 if the EVSE should wait indefinitely for PnC authorization. Applies to ISO 15118-2 and ISO 15118-20; DIN SPEC 70121 has no Plug-and-Charge. The default is the 55 s V2G_SECC_Ongoing_Performance_Time of [V2G2-712/713] and [V2G20-2102].
| **enable_ssl_logging**: *boolean* <optional>
| *default: False*
|  Verbosely log the ssl/tls connection
| **enable_tls_key_logging**: *boolean* <optional>
| *default: False*
|  Enable/Disable the export of TLS session keys (pre-master-secret) during a TLS handshake. Note that this option is for testing and simulation purpose only
| **tls_key_logging_path**: *string* <optional>
| *default: "/tmp"*
|  Output directory for the TLS key log file
| **enable_sdp_server**: *boolean* <optional>
| *default: True*
|  Enable the built-in SDP server
| **supported_dynamic_mode**: *boolean* <optional>
| *default: True*
|  The EVSE should support dynamic mode
| **supported_mobility_needs_mode_provided_by_secc**: *boolean* <optional>
| *default: False*
|  The EVSE should support the mobility needs mode provided by the SECC. Mobility needs mode provided by the EVCC is always provided.
| **supported_scheduled_mode**: *boolean* <optional>
| *default: False*
|  The EVSE should support scheduled mode
| **custom_protocol_namespace**: *string* <optional>
| *default: ""*
|  Providing a custom protocol namespace.
| **negative_bidirectional_limits**: *boolean* <optional>
| *default: True*
|  Some cars send or expect negative discharge limits. However, it is not clear from the standard whether the discharge limits should be negative. Until this is clarified, the positive limits can be converted using this option.
| **selecting_sap_based_on_energy_service**: *boolean* <optional>
| *default: False*
|  The SAP namespace matching the supported energy services is always preferred: a DC charger selects -20:DC (or -2 / DIN) and an AC charger -20:AC, even if the EV ranks the other -20 namespace higher. Based on ISO15118-20 AMD1, selecting the SAP namespace does not imply a final selection, so by default an EV offering only non-matching namespaces still gets one and selects its service later in the D20 service states. Set this option to true to refuse such namespaces instead (Failed_NoNegotiation).

|  Raises grid alarms from EV grid-event conditions and accepts active DER directives. Curve-family directives (VoltVar, WattVar, WattPF) are relayed to the EV as AC_DER_IEC control functions at the next V2G session; non-curve directives are logged and skipped.
