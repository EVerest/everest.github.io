evse_board_support_API¶

version 1.1.0AsyncAPI 3.0.0 content type application/jsonlicense Apache-2.0EVerestevse_board_supportac_rcdconnector_lock

EVerest API definition for EVSE board support

API for EVerest API clients implementing evse board support, AC RCD and connector lock. Commands without arguments carry an empty JSON object ({}) as payload.

Specification: evse_board_support_API.yaml · pionix:de:everest:evse_board_support_API

send the client publishes, EVerest consumes (10) receive EVerest publishes, the client consumes (13)

Servers¶

default mqtt

default local MQTT

Host
localhost:1883
Topic prefix
everest_api/1/evse_board_support/{module_id}
{module_id}

The ID of the module as defined in the EVerest config file.

Payload

Event stream from ControlPilot signal/relais.

send Send phase count available to car
Topic
everest_api/1/evse_board_support/{module_id}/m2e/ac_nr_of_phases

Direction: Module to EVerest

Message Send phase count application/json

Message send_ac_nr_of_phases

Instantaneous phase count available to car

Values outside 1..3 are rejected with a log warning. Not required at start: the initial phase count comes from max_phase_count_import of the capabilities.

Payload

integer PhaseCount

Number of phases

min 1max 3

send_capabilities¶

send Send hardware capabilities
Topic
everest_api/1/evse_board_support/{module_id}/m2e/capabilities

Direction: Module to EVerest

Message Send hardware capabilities application/json

Message send_capabilities

Hardware capabilities/limits. Publish them once after start, before the first charging session: on AC, EVerest does not offer current before it has them, and on AC and DC they set connector_type and supports_cp_state_E. Publish them again whenever a limit changes, e.g. when the maximum current drops because the hardware gets too hot.

Payload

object HardwareCapabilities

Hardware capabilities / limits

Definition of HardwareCapabilities

Current carrying capacity of the connected cable in ampere for AC charging with a socket. Publish whenever it changes. This has no meaning for DC or AC charging with a fixed attached cable, it does not need to be implemented and the returned value is not used in those cases.

receive_pwm_on¶

receive Receive PWM duty cycle
Topic
everest_api/1/evse_board_support/{module_id}/e2m/pwm_on

Direction: EVerest to Module

Message Receive PWM duty cycle application/json

Message receive_pwm_on

Turns PWM on with duty cycle (in percent)

EVerest only requests duty cycles strictly between 0 and 100 (5 % for high level communication, 10 % for 6 A up to 97 % for 80 A). State X1 (no current available, PWM off) is requested with cp_state_X1 and state F with cp_state_F, never as a duty cycle of 100 or 0 here.

Payload

number PWMDutyCycle

PWM duty cycle in percent, strictly between 0 and 100. EVerest requests 100 % (X1) and 0 % (F) through cp_state_X1 and cp_state_F instead.

min (exclusive) 0max (exclusive) 100

Example

receive_ac_switch_three_phases_while_charging¶

receive Receive command to switch 3 phase and 1 phase mode while charging
Topic
everest_api/1/evse_board_support/{module_id}/e2m/ac_switch_three_phases_while_charging

Direction: EVerest to Module

Message Receive request switch between 3 phase and 1 phase mode application/json

Message receive_ac_switch_three_phases_while_charging

Optional, in case of doubt do not implement. Report in hardware_capabilites if this command is supported. This command switches between one and three phase operation during an active charging session. Some cars can be permanently destroyed by that, so the bsp needs to implement a special sequence for the switching. The exact sequence can be defined by the BSP, but one example would be a C2->C1->B1->F->B1->B2->C2 or similar. Use with caution.

Payload

string ACPhaseMode

Number of active phases for AC charging

enumThreePhasesSinglePhase

Example

receive_ac_overcurrent_limit¶

receive Receive over current limit
Topic
everest_api/1/evse_board_support/{module_id}/e2m/ac_overcurrent_limit

Direction: EVerest to Module

Message Receive over current limit application/json

Message receive_ac_overcurrent_limit

Many chargers implement a fast over current shutdown directly in the hardware that triggers if the EV draws more current than the PWM allows. If the hardware does not have this functionality, just ignore this command. Do not use it to set the PWM duty cycle. Otherwise this command reports a value that should be used for the overcurrent detection. A margin needs to be added to avoid false triggers. Do not use the PWM duty cycle to infer the current limit in the BSP, as this will not work with HLC.

Payload

number OverCurrent

Electrical current in ampere (A)

Example

Many chargers implement a fast over current shutdown directly in the hardware that triggers if the EV draws more current than the PWM allows. If the hardware does not have this functionality, just ignore this command. Do not use it to set the PWM duty cycle. Otherwise this command reports a value that should be used for the overcurrent detection. A margin needs to be added to avoid false triggers. Do not use the PWM duty cycle to infer the current limit in the BSP, as this will not work with HLC.
